02

The Request Envelope: Plain-Text Structure

Slide 6 & Week 2 Session: HTTP is a plain-text conversation with three strict sections.

Inspect Verb Packet:
Section 1 Request Line (Verb + Resource Path + Protocol)
GET /r/python/about.json HTTP/1.1
Section 2 Headers (Metadata: Identity, Auth, Content Formats)
Host: www.reddit.com User-Agent: python:subreddit.assignment:v1.0 (by /u/kingsleykipkoech) Accept: application/json Connection: close
Section 3 Body / Content (Payload Data)
[EMPTY FOR GET REQUESTS - GET ONLY READS DATA]

HTTP GET Method

The GET method requests a representation of the specified resource. Requests using GET should only retrieve data and have no other effect.

Request Has Body: No
Safe (No Data Mutation): Yes
Idempotent (Repeatable): Yes
Cacheable by Proxies: Yes
03

The Response Envelope & Status Codes

Slide 11 & 14: Never assume success. The first line tells you if the server accepted your request.

200
OK (Success)
Server fulfilled request cleanly.
201
Created
New resource successfully stored.
301
Moved
Resource has moved permanently.
401
Unauthorized
Missing API key or token.
403
Forbidden
Reddit blocks automated scripts.
404
Not Found
Endpoint does not exist.
500
Server Error
Remote server code crashed.
Response Packet Preview: HTTP/1.1 200 OK 2xx SUCCESS
HTTP/1.1 200 OK Date: Wed, 21 Oct 2026 03:00:00 GMT Server: gunicorn / nginx Content-Type: application/json; charset=utf-8 Content-Length: 384 { "title": "NGC 5139 Globular Cluster", "media_type": "image", "hdurl": "https://assets.science.nasa.gov/.../NGC5139.jpg" }
Rule from Slide 14: "Never assume a request succeeded! Always check response.status_code == 200 before trying to read data."

05

Clean REST Design vs. Anti-Patterns

Slide 14 & 15: URLs are nouns (resources). The HTTP verb is the action.

Anti-Pattern (Bad RPC Style)
POST /createBook Bad: Uses verb in URL
POST /updateBook?id=4 Bad: Uses action in directory path
POST /deleteBookById Bad: Clutters namespace with methods
GET /getAllProfiles Bad: Redundant verb
Good RESTful Design (Clean Nouns)
POST /books Good: POST creates in collection
PUT /books/4 Good: PUT updates ID 4 directly
DELETE /books/4 Good: DELETE removes ID 4
GET /books Good: GET reads collection

Slide 19: Rule Number One — Statelessness

"As far as the REST-server is concerned, every call is the first call."
The server does not store session cookies or remember your past requests. You must send your User-Agent or api_key with every single call.
